## 5. 필요한 API

앱이 Supabase 에 직접 하는 것(RLS 보호)은 API 를 만들지 않는다. FastAPI 는 검사·계산·파일·추론만.

| 메서드·경로 | 역할 | Phase |
|---|---|---|
| `GET /health` | 서버·모델 상태 (`model_status`) | 3 |
| `GET /residual-curve?from&to` | 투약 기록 → 상대 잔존 곡선 (상대값만) | 3 |
| `POST /posts` · `PATCH /posts/{id}` · `DELETE /posts/{id}` | 금칙어·권한·입력값 검사 후 저장 | 3 |
| `POST /posts/{id}/comments` · `PATCH/DELETE /comments/{id}` | 댓글 동일 | 3 |
| `POST /admin/actions` | 관리자 조치 (서버에서 role 재확인, 사유 필수) | 3 |
| `POST /meals/photo` | 사진 업로드 → EXIF 제거 → Storage → 추론 → meals·predictions | 3·4 |
| `DELETE /meals/{id}` | 사진 기록 삭제 (파일 → 행) | 3 |
| `POST /body-logs/ocr` | OCR 확정값 2차 검증·중복 확인(409) 후 저장 | 4 |
| `DELETE /me` | 탈퇴: Storage 폴더 → Auth 사용자 삭제(cascade) | 3 |

모든 요청: `Authorization: Bearer <Supabase JWT>` → 서버가 JWKS 로 검증. 오류 형식 `{code, message, field}`.

## 6. AI 모델 구현 계획

| 단계 | 내용 | 어디서 |
|---|---|---|
| 데이터 | AI Hub 신청·다운로드(또는 안심존) → `inspect_labels.py`로 실측 → 멀티라벨/단일 결정 | **사용자 PC** (이 컨테이너는 aihub 접속 불가, 해외 반출 금지 조건) |
| 전처리·분할 | 클래스 매핑(목표 20종), 이미지 리사이즈, train/val/test 70/15/15, 같은 원본 사진이 갈라지지 않게 그룹 분할 | 사용자 PC (코드는 여기서 작성·테스트) |
| 학습 | timm EfficientNet-B0. A: 마지막 층만 / B: 마지막 블록들 미세조정 / (C: MobileNetV3) | 사용자 PC CPU (20종×수백 장이면 CPU 로 수 시간 수준 — 실측 필요) |
| 평가 | Macro-F1, 클래스별 P/R, 혼동행렬, CPU 지연시간. 테스트셋은 한 번만 | 사용자 PC → 결과 JSON 을 저장소에 |
| 배포 | ONNX 변환 → FastAPI 에서 onnxruntime 추론. `model_versions`에 실측값만 기록 | 서버 |
| 미지원 음식 | 기준값 미만이면 "확인 필요"/"인식 못 함" → 검색으로 수동 입력 | 앱 |

- 여기서 할 수 있는 것: 학습·평가·변환 코드 전체 + **작은 가짜 이미지로 코드가 끝까지 도는지** 테스트.
- 여기서 못 하는 것: 실제 데이터 학습과 실제 성능 수치. **실제 평가 전에는 정확도를 쓰지 않는다.**
- 신뢰도 표시: 2026-11-03 결정(신뢰도 % 보류)을 따른다. 화면은 "인식 결과 / 확인 필요", 점수는 내부 저장. % 표시가 필요하면 다시 결정 필요.

## 9. 최종 완료 판정 기준

기능 하나를 "완료"로 표시하려면 전부 만족:
1. 실제 사용자 입력으로 동작 (목업 모드 아님)
2. 실제 DB(또는 눈바디처럼 지정된 로컬 저장소)에 저장
3. 새로고침·재로그인 후에도 유지
4. 수정·삭제 동작
5. 다른 사용자 데이터와 분리 (RLS 테스트 또는 API 테스트로 확인)
6. 오류·빈 상태·로딩 처리
7. 해당 기능 자동 테스트 통과 (로컬 Supabase 기준 E2E)
8. 기존 테스트(목업 모드 284개, RLS 45개 등) 회귀 없음

상태 표기: `완료` / `코드 완료·외부 조치 대기` (예: OAuth 키 없음) / `진행 중` / `미착수`

## 개발 방식 (Phase 1 부터 적용)

- **데이터 모드 스위치:** `VITE_SUPABASE_URL`이 있으면 실서비스 모드, 없으면 기존 목업 모드.
  → 미리보기·기존 테스트 284개는 목업 모드로 그대로 유지, 새 기능은 실서비스 모드 E2E 로 검증
- **개발 DB:** 이 컨테이너의 로컬 Supabase(공식 CLI) → 클라우드와 같은 마이그레이션
- **개발용 로그인:** 개발 빌드 + 로컬 Supabase 에서만 이메일 테스트 계정 로그인 노출 (운영 빌드에서는 제거). OAuth 는 자동 테스트가 불가능해서 같은 Auth 세션 흐름을 이걸로 검증
- **목업 표시:** 실서비스 모드에서는 "목업" 배지·예시 데이터가 나오면 안 됨. 아직 연결 안 된 화면은 "준비 중"으로 정직하게 표시
