# 눈바디 잠금 설계 v2 (갤럭시 전용 Capacitor 앱)

목표: 눈바디 사진은 기기에만 암호화해서 저장한다. 잠금은 비밀번호, 지문(Android 생체인증), 복구 코드 3가지로 풀 수 있다. 비밀번호를 잊으면 지문이나 복구 코드로 다시 정한다.

## 1. 기존 구조 (v1) 분석

| 항목 | v1 |
|---|---|
| 저장소 | IndexedDB `slimlog-eyebody[-userId]`, store `meta` / `photos` |
| 열쇠 | 비밀번호 → PBKDF2-SHA256(31만 회, salt 16B) → AES-GCM-256. **비밀번호에서 만든 열쇠로 사진을 바로 암호화** |
| 확인값 | `meta.key = { salt, iv, check }`. check = 'slimlog-eyebody-ok' 암호문 |
| 사진 | 행마다 `iv, data(원본 1600px), thumbIv, thumb(320px)`, 새 IV 12B |
| 문제 | 비밀번호와 데이터 열쇠가 같아서 비밀번호 변경·분실 복구·지문 잠금을 넣을 수 없음 |

## 2. 새 구조 (v2): 데이터 열쇠와 비밀번호 분리

```
           ┌─ 비밀번호 ─ PBKDF2(60만 회, salt) ─ KEK ─┐
DEK(32B 난수) ┼─ 복구 코드 ─ PBKDF2(10만 회, salt) ─ KEK ─┼─ 각각 AES-GCM 으로 DEK 를 감싸서 meta 에 저장
           └─ 지문 ─ Android Keystore RSA(인증 필수) ────┘  (플러그인 보안 저장소)
사진 원본·썸네일 = AES-GCM(DEK, 새 IV)
```

- **DEK**: `crypto.getRandomValues(32)`. 사진은 DEK 로만 암호화한다
- **비밀번호 KEK**: PBKDF2-SHA256, 60만 회(OWASP 권장), 금고별 salt 16B. 반복 횟수는 meta 에 저장해서 나중에 올릴 수 있다
  - Argon2 는 WebCrypto 에 없어서 wasm 의존성이 필요함 → 이번엔 PBKDF2 를 유지하고, 필요하면 나중에 교체(meta 에 kdf 이름 저장)
- **복구 코드**: 24자 Crockford Base32(헷갈리는 I·L·O·U 제외) = **120비트**. 4자씩 끊어서 표시. KEK 는 PBKDF2 10만 회 (코드 자체 엔트로피가 충분함)
- **지문**: `@capgo/capacitor-native-biometric@8.9.1` `setData/getSecureData`
  - `accessControl: BIOMETRY_CURRENT_SET`, `authValidityDuration: 0`
  - 소스 확인: Keystore RSA-2048 OAEP, `setUserAuthenticationRequired(true)`, `setUserAuthenticationParameters(0, AUTH_BIOMETRIC_STRONG)`, `setInvalidatedByBiometricEnrollment(true)`, 읽을 때 BiometricPrompt CryptoObject 로 인증된 열쇠로만 풀림
  - 지문을 새로 등록하면 열쇠가 무효가 됨 → 비밀번호나 복구 코드로 연 뒤 지문을 다시 켜기
- **확인값**: `check = AES-GCM(DEK, 'slimlog-eyebody-ok')`. 잘못된 비밀번호는 GCM 인증 실패로 걸러짐
- DEK 원본 바이트는 감싸기·풀기 순간에만 쓰고, 열린 동안엔 **추출 불가 CryptoKey** 로만 메모리에 둔다

### meta 레코드
- `v2`: `{ version: 2, pw: {kdf, salt, iter, iv, wrapped}, rc: {...}, rcConfirmed, check: {iv, data}, bio: boolean, migration: 'pending' | 'done' }`
- `key`(v1): 마이그레이션이 끝날 때까지 지우지 않음

### 사진 행
- `v: 2` 가 있으면 DEK 로 암호화된 행, 없으면 v1(비밀번호 열쇠) 행

## 3. 비밀번호 분실 처리
1. 지문 → DEK → 새 비밀번호로 다시 감싸기
2. 복구 코드 → DEK → 새 비밀번호 (복구 코드는 그대로 유효, 원하면 새로 발급)
3. 둘 다 없음 → 전부 지우고 새로 시작 (암호화 특성상 복구 불가, 화면에 명시)

## 4. 기존 데이터 이전 (v1 → v2)
비밀번호로 처음 열 때 진행한다.
1. v1 열쇠로 check 확인
2. DEK 생성 → 비밀번호·복구 코드로 감싸서 `meta.v2` 저장 (`migration: 'pending'`). **`meta.key` 는 그대로 둠**
3. 사진 행마다: v1 열쇠로 풀기 → DEK 로 암호화 → **새 암호문을 다시 풀어서 원본과 바이트 비교** → 같을 때만 같은 id 로 덮어쓰기 (`v: 2`). 행 단위 트랜잭션이라 중간에 꺼져도 행은 '옛것' 아니면 '새것'
4. 모든 행이 v2 면 `meta.key` 삭제 + `migration: 'done'` (한 트랜잭션)
5. 중간에 꺼지면 다음 비밀번호 잠금 해제 때 남은 행부터 이어서 진행. pending 동안은 비밀번호 변경 막음
- 복구 코드로 열었는데 pending 이면: v2 행은 보이고, 남은 v1 행은 "비밀번호로 한 번 열어야 옮겨져요" 안내

## 5. 평문이 남지 않게
- 웹: 저장 전에 캔버스로 다시 그려 EXIF 제거, 원본 File 은 메모리에서만. 복호화한 사진은 `blob:` URL(메모리) → 화면을 떠나면 revoke
- 앱(4단계): 카메라·앨범 임시 파일이 cache 디렉터리에 생기는지 확인하고, 가져온 직후 지운다. 썸네일·원본 모두 암호화해서만 저장

## 6. 백업·재설치 정책
- **Android 자동 백업 끔** (`allowBackup=false` + `dataExtractionRules` 전부 제외). "기기에만 저장" 약속과 맞춤
  - 백업을 허용하면 암호문은 구글 드라이브로 복원되지만 Keystore 열쇠는 복원되지 않음 → 지문 잠금은 깨지고 비밀번호·복구 코드로만 열림. 이번엔 쓰지 않음
- 앱 삭제·재설치: 사진·열쇠 모두 사라지고 복구 불가 (안내 문구 고정: "사진은 현재 기기에만 저장되며, 앱 삭제·데이터 삭제·기기 변경 시 복구되지 않을 수 있습니다")

## 7. 자동 잠금·최근 앱 화면
- 앱이 백그라운드로 가면 **바로 잠금** (카메라·앨범을 여는 동안만 예외)
- 화면에 있어도 **5분 동안 손대지 않으면 잠금**
- 백그라운드로 가는 순간 사진을 화면에서 가림 (웹)
- 앱(4단계): 눈바디 화면에서 `FLAG_SECURE` → 최근 앱 화면에 사진 안 보이고 캡처 막힘

## 8. 바뀌는 범위 (영향)
| 파일 | 바뀌는 것 |
|---|---|
| `src/lib/eyebodyVault.ts` | 열쇠 구조 v2, 복구 코드, 마이그레이션, 비밀번호 변경·재설정, 지문용 DEK 내보내기/가져오기, 자동 잠금 규칙 |
| `src/lib/biometric.ts` (새) | 지문 저장소 연결부. 웹은 '사용 불가', 앱은 플러그인 (4·5단계) |
| `src/features/record/eyebody/*` | 잠금 화면(복구 코드 저장 단계, 비밀번호 잊었어요 → 지문/복구 코드/전부 지우기), 설정(비밀번호 변경, 복구 코드 새로 만들기, 지문 잠금) |
| `src/features/my/EyebodyDataPage.tsx` | 전부 지우기 때 지문 저장값도 지움 |
| 테스트 | 예전 금고 → v2 이전 검증, 복구 코드·비밀번호 재설정 |
- 사진 화면(기록 보기·변화 비교·캘린더)은 그대로
- 다른 메뉴는 안 바뀜

## 9. 4단계 반영 (Capacitor Android) — 소스 재검증 결과

플러그인 `@capgo/capacitor-native-biometric@8.9.1`, 우리가 쓰는 경로 `setData(accessControl=BIOMETRY_CURRENT_SET(1), authValidityDuration=0)` → `getSecureData`

| 항목 | 소스 위치 | 결과 |
|---|---|---|
| 열쇠 종류 | `AsymmetricSecureDataHelper.generateKeyPair` | Keystore RSA-2048, OAEP(SHA-256) |
| 인증 필수 | 같은 곳 | `setUserAuthenticationRequired(true)` |
| 인증 방식·유효시간 | 같은 곳 | API 30+: `setUserAuthenticationParameters(0, AUTH_BIOMETRIC_STRONG)` = 매번, 강한 생체만. API 24~29: `setUserAuthenticationValidityDurationSeconds(-1)` = 매번 |
| 지문 재등록 시 무효화 | `getOrCreateKeyPair` | accessControl==1 이면 `setInvalidatedByBiometricEnrollment(true)` |
| ⚠️ 무효화 실패 시 | 같은 곳 | **원본은 ProviderException 이면 무효화 없이 다시 생성(조용한 후퇴)** → `patches/@capgo+capacitor-native-biometric+8.9.1.patch` 로 **실패 처리**하게 바꿈. 앱은 지문 잠금을 켜지 않고 안내 |
| 지문 창 허용 방식 | `AuthActivity` + `BiometricAuthenticatorConfig.ensureCryptoCompatible` | 약한 생체(갤럭시 얼굴인식)·PIN 이 섞이면 `BIOMETRIC_STRONG` 만으로 바꿈 |
| 풀기 | `AuthActivity` getSecureData → `decryptPayload(result.getCryptoObject().getCipher())` | 지문 창에서 인증된 cipher 로만 풀림 |
| 저장 위치 | SharedPreferences `NativeBiometricSharedPreferences` (암호문) | 자동 백업 제외(아래), 앱 삭제 시 함께 삭제 |

### Android 설정
- `AndroidManifest.xml`: `allowBackup=false`, `fullBackupContent=false`, `dataExtractionRules=@xml/data_extraction_rules`(클라우드 백업·기기 이전 모두 제외)
- `CAMERA` 권한 미선언: 촬영은 기본 카메라 앱에 맡기고 결과만 받음 (권한 요청 없음)
- `file_paths.xml`: FileProvider 공개 범위를 외부 저장소 전체(`.`) → 촬영 임시 폴더(`Pictures/`)로 좁힘
- 촬영 임시 파일: Capacitor 가 `getExternalFilesDir(Pictures)` 에 평문 JPG 생성 → 앱이 메모리로 읽은 직후 `SecureScreen.clearCaptureFiles()` 로 삭제, 앱 시작 때도 삭제 (눈바디·식단 모두)
- `FLAG_SECURE`: `SecureScreenPlugin.setSecure` — 눈바디 화면에 들어갈 때 켜고 나갈 때 끔. 다른 화면은 적용 안 함
- 로그인: 앱에서는 Custom Tabs(시스템 브라우저)로 열고 `com.slimlog.app://auth-callback` 딥링크로 복귀 → `exchangeCodeForSession`
