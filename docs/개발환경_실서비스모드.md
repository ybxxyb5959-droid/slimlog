# 개발 환경 — 목업 모드 / 실서비스 모드

## 두 가지 모드
| 모드 | 조건 | 용도 |
|---|---|---|
| 목업 | `VITE_SUPABASE_URL` 없음 | 미리보기, 기존 화면 테스트 284개 |
| 실서비스(live) | `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` 있음 | 실제 로그인·DB |

코드: `src/lib/supabase.ts` (`isLive`), 각 서비스(`src/services/*`)가 모드에 따라 목업 스토어 또는 Supabase 를 쓴다.

## 로컬에서 실서비스 모드로 띄우기
```bash
npx supabase start
```
```bash
npx supabase status -o env
```
위 출력의 `API_URL`, `ANON_KEY` 를 `.env.local` 에 넣는다 (`.env.example` 참고, `VITE_DEV_LOGIN=1`).
```bash
npx vite
```
- 로컬 Supabase 에는 카카오·구글 키가 없어서 버튼이 "준비 중"으로 나온다 → 개발용 이메일 로그인 사용
- 개발용 로그인은 `import.meta.env.DEV` + `VITE_DEV_LOGIN=1` 일 때만 보인다 (운영 빌드에는 없음)

## 테스트
| 무엇 | 명령 |
|---|---|
| 목업 화면 (284개) | `PW_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test` |
| 실서비스 E2E (로컬 Supabase) | `PW_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test -c playwright.live.config.ts` |
| DB RLS 45개 + Auth·Storage 30개 | `bash supabase/tests/run_local.sh` |
| AI 라벨 도구 21개 | `python3 -m unittest discover -s ai/tests -t .` |

## DB 타입 다시 만들기 (마이그레이션 바꾼 뒤)
```bash
npx supabase gen types typescript --local > src/types/database.ts
```

## 로그인 흐름 (live)
1. `/login` → 카카오·구글 `signInWithOAuth` (켜진 공급자만, `GET /auth/v1/settings` 로 확인)
2. 공급자 로그인 → `/auth/callback?code=…` → Supabase 가 세션으로 교환 (PKCE)
3. `authStore` 가 `users`·`user_health`·`consents` 를 불러옴 → 필수 동의 없으면 `/consent`, 온보딩 안 끝났으면 `/onboarding`, 아니면 `/home`
4. 화면 출입은 `LiveGate`(`src/features/auth/LiveGate.tsx`) 가 관리
